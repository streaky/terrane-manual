# 3. Making Decisions and Repeating Work

A useful program rarely performs every operation exactly once. It chooses work according to current values, and it repeats work over changing state or a sequence of items.

Terrane expresses those ideas with a small family of indentation-based statements:

```terrane
if condition
  work

while condition
  work

for item in things
  work
```

The surface is compact, but the choices matter. An `if` selects among alternatives. A `while` repeats while a condition remains true. A `for` asks an object for its sequence of items. `break` and `continue` alter the current loop without disguising that change inside an expression.

By the end of this chapter, you will be able to:

- choose between branches with `if`, `else if`, and `else`;
- combine conditions with `and`, `or`, and `not`;
- repeat state-driven work with `while`;
- iterate over strings and ranges with `for`;
- leave or skip within a loop;
- reason about names created by loop bodies;
- choose the loop that communicates the program's intent;
- classify a range of numbers in a complete program.

## Choosing with `if` and `else`

An `if` evaluates a condition and runs its indented body when that condition is true:

```terrane
if total <= budget
  print; 'Purchase approved'
```

When the comparison is false, the body is skipped.

Add `else` for the alternative:

```terrane
if total <= budget
  print; 'Purchase approved'
else
  print; 'Over budget'
```

`else` aligns with its `if`. The two indented bodies are distinct blocks, and exactly one runs.

A complete program might look like this:

```terrane
namespace budget-decision

function main;
  total = 22
  budget = 20

  if total <= budget
    print; 'Purchase approved'
  else
    print; 'Over budget'
```

It prints:

```text
Over budget
```

The condition is an ordinary expression. Here, `<=` compares two integers and produces a boolean. Terrane evaluates that value before choosing a branch.

### More than two alternatives

Use `else if` when alternatives are tested in order:

```terrane
if temperature < 0
  print; 'freezing'
else if temperature < 15
  print; 'cold'
else if temperature < 25
  print; 'mild'
else
  print; 'warm'
```

The conditions are considered from top to bottom. The first true condition wins, and later alternatives are not evaluated. The final `else` handles everything not accepted earlier.

Order therefore carries meaning. This arrangement works because each later branch receives values excluded by earlier ones. If `temperature < 25` appeared first, both freezing and cold temperatures would be reported as mild enough for that broad condition.

### Indentation is the block

There are no braces around a branch. Statements belong to it because they are indented:

```terrane
if ready
  print; 'starting'
  started = true
print; 'decision finished'
```

The first two statements are conditional. The final `print` aligns with `if`, so it runs after the decision whichever branch was taken.

Readable indentation is therefore part of correctness, not decoration supplied after parsing.

## Combining conditions

Boolean operators let one decision depend on several facts:

| Operator | Meaning |
|---|---|
| `and` | both conditions must be true |
| `or` | at least one condition must be true |
| `not` | reverse one condition |

Examples:

```terrane
if has-ticket and door-open
  print; 'enter'

if is-admin or owns-document
  print; 'editing allowed'

if not finished
  print; 'work remains'
```

`not` applies to the expression immediately following it. Parentheses can make a larger intended unit explicit:

```terrane
if not (is-admin or owns-document)
  print; 'read only'
```

### Short-circuit evaluation

`and` and `or` evaluate from left to right and short-circuit.

For `and`, a false left side already decides the result, so the right side is not evaluated:

```terrane
available and permitted
```

For `or`, a true left side already decides the result:

```terrane
cached or available
```

This is useful both for efficiency and safety. A later expression can rely on a condition established earlier:

```terrane
if count != 0 and total / count > 10
  print; 'average is high'
```

When `count` is zero, the division is never evaluated.

Short-circuiting should support a clear condition, not hide a sequence of unrelated side effects. If several operations must visibly happen, write statements.

### Write each comparison

Comparisons do not chain in Terrane. To check a range, combine two complete comparisons:

```terrane
if minimum <= value and value <= maximum
  print; 'inside range'
```

This is rejected:

```terrane
if minimum <= value <= maximum
  print; 'inside range'
```

The explicit form makes both relationships and the shared value visible.

### Conditions are object behavior

A condition is not defined as “anything nonzero” or “anything nonempty.” It is evaluated through Terrane's truth behavior. Booleans and comparison results are the clearest everyday inputs:

```terrane
if ready
  print; 'ready'

if count > 0
  print; 'items available'
```

Do not depend on accidental truthiness borrowed from another language. Write the condition the program means.

## Repeating with `while`

A `while` loop repeats its body while its condition remains true:

```terrane
countdown = 3
while countdown > 0
  print; countdown
  countdown--
print; 'go'
```

The loop proceeds as follows:

1. evaluate `countdown > 0`;
2. if false, leave the loop;
3. if true, run the indented body;
4. return to the condition.

The output is:

```text
3
2
1
go
```

The body changes `countdown`, eventually making the condition false. Without that update, the loop would continue indefinitely:

```terrane
while countdown > 0
  print; countdown          # countdown never changes
```

An infinite loop may occasionally be intentional, but it should be a deliberate property of the program rather than a missing state transition.

### Use `while` for state-driven repetition

`while` is a natural fit when continuation depends on evolving state:

```terrane
attempts = 0
connected = false

while attempts < 3 and not connected
  attempts++
  # Try one connection operation here.
```

The program cannot describe the loop merely as “visit every item in this collection.” It must reconsider a condition after each attempt.

Keep the variables controlling that condition easy to find. A `while` body that changes its own exit state in many distant places is difficult to reason about.

## Iterating with `for`

A `for` loop visits the items produced by an iterable object:

```terrane
for character in 'Terrane'
  print; character
```

On each iteration, `character` is bound to the next item. Strings iterate as Unicode grapheme clusters, so a user-perceived character remains one item even when its encoding contains several code points.

A `for` loop says two things directly:

- which object supplies the sequence;
- which name denotes the current item.

It does not require a manual index, an explicit length check, or an update statement.

### Iteration uses a protocol

`for` is not limited to one built-in storage type. It asks the object on its right to provide ordinary iteration behavior.

That distinction becomes useful as the language grows. Strings, ranges, lists, maps, and user-defined iterable objects can participate through one loop form without pretending they have the same representation.

The loop consumes the sequence of yielded items until the iterator reports its distinct end state. End-of-iteration is not represented by `none`, because `none` may itself be a valid item.

You do not need to invoke the iteration protocol manually for ordinary loops. The `for` statement is its direct language surface.

## Ranges and ordinary iteration

A range represents a numeric progression. It is an ordinary object supplied by `/core/collections`, so import it explicitly:

```terrane
from /core/collections import range
```

Construct a half-open range with a start and an end:

```terrane
numbers = range; 1, 5
```

Iterating it yields:

```text
1
2
3
4
```

The end value, `5`, is excluded. Use it with `for`:

```terrane
numbers = range; 1, 5
for number in numbers
  print; number
```

Half-open ranges work naturally with counts and boundaries. A range from zero to a collection length contains exactly the valid forward indices when that collection uses zero-based indexing.

### Steps and direction

A third argument supplies the step:

```terrane
even-numbers = range; 0, 10, 2
```

This yields `0`, `2`, `4`, `6`, and `8`.

A negative step counts downward:

```terrane
countdown = range; 5, 0, -1
```

This yields `5`, `4`, `3`, `2`, and `1`.

A step may not be zero. A step whose direction cannot approach the endpoint produces an empty range rather than silently reversing direction:

```terrane
empty = range; 0, 5, -1
```

### Inclusive ranges are explicit

When the endpoint should be included, use the `through` member:

```terrane
numbers = range.through; 1, 5
```

This yields `1` through `5`.

The separate spelling keeps the boundary choice visible. A reader need not remember whether one particular loop context quietly includes an endpoint.

### Prefer items over indices

If the program needs each item, iterate the items:

```terrane
for character in text
  print; character
```

Do not introduce a range and index merely because another language taught iteration that way. Use indices when the index itself has meaning or when the operation genuinely requires positional lookup.

## `break` and `continue`

`break` leaves the nearest enclosing loop immediately:

```terrane
number = 1
while number <= 10
  if number == 4
    break
  print; number
  number++
```

This prints `1`, `2`, and `3`. When `number` reaches `4`, execution continues after the loop.

`continue` skips the remainder of the current iteration and begins the next one:

```terrane
numbers = range; 1, 6
for number in numbers
  if number == 3
    continue
  print; number
```

This prints `1`, `2`, `4`, and `5`.

Neither statement produces a value. They are visible control-flow operations.

### Order updates carefully in `while`

A `continue` in a `while` loop can accidentally skip the update that would make progress:

```terrane
number = 0
while number < 5
  if number == 2
    continue                 # number never advances beyond 2
  number++
```

Move the update before the possible `continue`, or restructure the condition:

```terrane
number = 0
while number < 5
  number++
  if number == 2
    continue
  print; number
```

A `for` loop advances its iterator as part of the loop machinery, so `continue` naturally requests the next item.

### Use early loop control to flatten code

`continue` can keep the main work from becoming deeply nested:

```terrane
for number in numbers
  if number < 0
    continue

  print; 'nonnegative: ', number
```

Similarly, `break` can state that a search is complete:

```terrane
for character in text
  if character == ':'
    break
  print; character
```

Use these statements when they reveal the loop's control decision. Too many exits scattered through a large body make the same loop harder to understand.

## Loop-local names

A `for` target belongs to the loop body:

```terrane
for number in numbers
  print; number
```

After the loop, `number` is no longer available. The name describes the current item, and there is no current item once iteration ends.

Names first created inside the body are local to that body too:

```terrane
for number in numbers
  doubled = number * 2
  print; doubled

print; doubled               # rejected: doubled is out of scope
```

This prevents a value from accidentally leaking out of a loop where it may never have been initialized. An empty iterable would run the body zero times, so there would be no reliable final `doubled` value.

### Updating an outer binding

A name declared before the loop remains visible inside it. Assigning to that existing binding updates it:

```terrane
total = 0
numbers = range; 1, 4

for number in numbers
  total = total + number

print; total
```

The result is `6`.

This pattern is appropriate for an accumulated result. The loop target `number` remains local, while `total` was deliberately established as state that survives the loop.

### Each target is an ordinary local value

Changing the loop target does not rewrite the iterated object:

```terrane
for character in 'abc'
  character = 'changed'
  print; character
```

The target is a local binding for the current item. Terrane's ordinary value semantics do not turn it into a hidden reference to the source collection.

When a program intends to mutate collection elements in place, it should use the collection's explicit mutation operations rather than relying on loop-variable aliasing. Chapter 5 develops that distinction.

## Choosing the clearest loop

Terrane offers more than one way to express some repetitions. Choose the one that tells the reader why repetition continues.

Use `for` when the program visits items from an iterable:

```terrane
for character in text
  print; character
```

Use `while` when repetition depends on changing state:

```terrane
while attempts < limit and not connected
  attempts++
```

Use `break` when the loop's purpose may finish before its natural end:

```terrane
for character in text
  if character == ':'
    break
```

Use `continue` when one item should be skipped and the main path should remain visually clear:

```terrane
for number in numbers
  if number < 0
    continue
  print; number
```

Terrane also supports a three-clause `for` for genuinely index-driven work:

```terrane
for index = 0; index < 3; index++
  print; index
```

The semicolons in this form delimit the loop's clauses; they are not call markers. Calls used inside those clauses must be grouped. Prefer ordinary `for item in items` when it states the job directly.

### Avoid clever equivalence

A `while` loop can imitate a `for`, and a `for` can carry enough state to imitate many `while` loops. Syntactic possibility is not a reason to choose the less direct form.

This:

```terrane
numbers = range; 0, 5
for number in numbers
  print; number
```

states its finite sequence more clearly than manually maintaining the same counter in a `while` loop.

Conversely, retrying until success is state-driven behavior. Hiding it inside a fabricated range of possible attempts can obscure the condition that actually matters.

## Project: classify a range of numbers

We will finish with a small program that combines ranges, iteration, ordered decisions, arithmetic, and boolean conditions.

Create `number-classifier.trn`:

```terrane
namespace number-classifier

from /core/collections import range

function main;
  numbers = range; -3, 5

  for number in numbers
    if number == 0
      print; number, ': zero'
    else if number % 2 == 0 and number < 0
      print; number, ': negative even'
    else if number < 0
      print; number, ': negative odd'
    else if number % 2 == 0
      print; number, ': positive even'
    else
      print; number, ': positive odd'
```

Run it:

```console
terrane run number-classifier.trn
```

The output is:

```text
-3: negative odd
-2: negative even
-1: negative odd
0: zero
1: positive odd
2: positive even
3: positive odd
4: positive even
```

The range is half-open, so `-3` is included and `5` is not.

Within the loop, the branch order narrows the remaining possibilities:

1. zero is handled first because it is neither positive nor negative;
2. a negative number divisible by two is negative and even;
3. any remaining negative number is odd;
4. a remaining number divisible by two is positive and even;
5. every remaining number is positive and odd.

The condition:

```terrane
number % 2 == 0
```

asks whether division by two leaves no remainder. Combining it with `number < 0` distinguishes the negative-even branch.

We could repeat the even test in every branch, but the ordered structure lets each later condition rely on what earlier conditions have excluded. The program remains readable because every branch prints one complete classification.

### Try a different interval

Change the range:

```terrane
numbers = range; -5, 8
```

The branch logic needs no modification. Input selection and classification are separate decisions.

For an inclusive upper endpoint, use:

```terrane
numbers = range.through; -5, 8
```

The changed constructor makes the boundary choice visible at the value's creation.

Chapter 4 will move the classification work into a function. That refactoring will let us reuse and test the decision independently of the loop that supplies numbers.

## What we learned

`if`, `else if`, and `else` choose among ordered alternatives. Conditions use truth behavior; comparisons provide clear booleans, and `and`, `or`, and `not` combine them. `and` and `or` short-circuit from left to right.

A `while` loop repeats according to changing state. A `for` loop visits the items supplied by an iterable object. Ranges are ordinary imported collection objects: `range; start, end` is half-open, `range.through; start, end` includes the endpoint, and an optional nonzero step determines progression.

`break` leaves the nearest loop, while `continue` skips to its next iteration. Loop targets and names introduced in a loop body do not escape that body. Bindings deliberately created before a loop can accumulate results that survive it.

The clearest loop advertises why repetition continues: items suggest `for`, evolving state suggests `while`, completed searches suggest `break`, and excluded items may suggest `continue`.
